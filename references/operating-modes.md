# Operating modes

## Start

Use when no current `SHIP_PLAN.md` exists or the project must be reset.

Expected result:

- One shipping sentence.
- One smallest complete version.
- Must-ship and deferred scope.
- Execution controls created.
- First observable slice produced.

## Continue

Use when a current sprint exists.

Expected result:

- One session outcome.
- One vertical slice completed.
- Relevant verification run.
- `PROGRESS.md` updated.
- One next action selected.

## Scope check

Use for proposed features, dependencies, redesigns, abstractions, integrations, automation, and refactors.

Expected result:

- Classification: Required now, Useful later, or Avoid.
- Ship criterion unblocked.
- Simpler alternative considered.
- Cost paid through reduced or delayed scope.

## Friday review

Use weekly.

Expected result:

- Evidence-based progress summary.
- Drag identified.
- One deliverable committed for next Friday.
- Explicit not-now list.
- Recovery slice completed when evidence is absent and tools allow.

## Ship review

Use before release or handoff.

Expected result:

- Release checklist compared with evidence.
- Automated and manual checks run where possible.
- Blockers separated from post-release improvements.
- Release or handoff completed when authorized.
